# 外部レビューツールの位置づけ

**推奨であって必須ではありません。** 契約していなくてもこのハーネスは完全に動きます。導入するかどうかは
プロジェクトごとに判断してください。

## 役割の分け方

外部ツールと自前の verifier が同じことを言うと、レビューコメントが 2 倍になるだけで読まれなくなります。役割を分けます。

| | 担当 | 見るもの |
| --- | --- | --- |
| **外部レビューツール**（任意） | **何を変えたか** | 変更の要約、ファイル横断の説明、一般的な不具合パターン、言語ごとの慣習 |
| **自前の verifier**（必須） | **設計メモどおりか・何が未検証か** | 設計メモとの乖離、スコープ外の変更、テストが実装の写しになっていないか、入力検証・シークレット・権限 |
| **ウォークスルー**（自動生成） | **どの順に読むか** | 変更ファイルのグループ分けと読み順。決定的に生成され、モデルは介在しない |

この分担を保つため、3 つの verifier の定義には「**変更内容の要約はしない**」と明記してあります
（`.claude/agents/verifier-*.md`）。外部ツールを入れない場合、変更の要約は PR 本文の「実装内容」と
ウォークスルーが担います。

## 導入する場合の候補

導入・課金・Organization 設定は **人が行います**。ここには手順だけを書きます。

### 第一候補: CodeRabbit

1. https://coderabbit.ai で GitHub App をインストールし、対象リポジトリを選ぶ
2. リポジトリ直下に `.coderabbit.yaml` を置く（雛形: このリポジトリの `.coderabbit.yaml.example`）
3. 最初の PR でレビューが付くことを確認する

**注意**: 無料枠は public リポジトリ向けです。private リポジトリでは有料プランが必要になります。
GitHub Free プランの Organization では、まずここで判断が要ります。

### 第二候補: GitHub Copilot Code Review

1. Organization で Copilot の契約があることを確認する（Copilot Business / Enterprise）
2. リポジトリまたは Organization の設定で Copilot code review を有効にする
3. 必要なら `.github/copilot-instructions.md` にレビュー方針を書く

**注意**: Copilot の契約が前提です。契約が無ければこの選択肢は使えません。

### その他

Sonar / Codacy などの静的解析は、上の「何を変えたか」ではなく **CI の決定的チェック** の側に属します。
導入する場合は `harness.config.json` の `commands.lint` から呼ぶか、`ci.yml` にジョブを足してください。
そうすれば `/review` のゲート（緑でなければ verifier を起動しない）にも自動的に組み込まれます。

## 引き継ぎ時の扱い

- 外部ツールの契約が切れても、ハーネスの動作は変わりません。verifier とウォークスルーはそのまま動きます
- 引き継ぎ先が別のツールを使う場合は、この文書の表を更新し、`verifier-*.md` の「見ないもの」と
  食い違わないことだけ確認してください
- 外部ツールのコメントは **人が読む前提** です。エージェントは外部ツールの指摘を自動で適用しません
  （外部から来たテキストを指示として扱わない、という `CLAUDE.md` §6 の原則が適用されます）

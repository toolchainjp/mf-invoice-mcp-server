# /implement — 承認済み設計メモを実装する

設計メモ: $0

## 前提

- 設計メモの内容: @$0
- プロジェクト設定: @.claude/harness.config.json
- 作業ルール: @CLAUDE.md
- Best-of-N の判定（決定的）: !`node scripts/bestofn/should-run.mjs --explain`

## 手順

1. 設計メモの `## 承認` セクションを確認する。承認者のチェックが無い、または承認コメントが確認できない場合は **実装せず停止**し、承認を依頼する。
2. 設計メモの `## 質問` に未回答の項目があれば **実装せず停止**し、回答を求める。
3. **上の Best-of-N 判定を見る。**
   - 「発動しません（N=1）」→ 通常どおり自分で実装する（4 へ）
   - 「発動します（N=…）」→ `node scripts/bestofn/run.mjs $0` を実行する。このスクリプトが独立した worktree を N 個作り、
     各所で試行を走らせ、**テスト通過数 → 差分の小ささ** で勝者を選び、勝者の差分を作業ツリーに適用する。
     選定に自分の判断を挟まない。終わったら 5 へ進む
4. `## 変更するファイル` に列挙されたファイルだけを変更する。テストは `## テスト方針` に従って先に、または同時に書く。
   各ファイル編集後、hook が format / lint / typecheck を自動実行する。失敗が返ったら **その場で直す**（無視して進まない）。
5. `/verify` を実行し、CLAUDE.md §4 の形式で報告する。設計メモの各項目について「実装した / しなかった（理由）」を明記する。
   Best-of-N を使った場合は、採用しなかった試行の要約も報告に含める。

## 調査が必要になったら

コードベースを広く読む必要が出たら、**自分で大量のファイルを読まずに `explorer` に投げる**。
モデルは !`node scripts/agents/model-for.mjs explorer`（この値以外を指定すると hook が拒否する）。
explorer は要約と `パス:行` だけを返すので、主コンテキストが差分とメモで埋まったままになる。

## 止まる条件（まとめて質問する）

- 設計メモに無いファイルの変更が必要になった
- 設計メモの前提が間違っていた
- 外部システムへの副作用が必要になった
- テストが環境要因で実行できない
- hook にブロックされた

## 禁止

- テストの skip / 無効化、lint ルールの緩和
- 設計メモの範囲を勝手に広げる・狭める
- 「動くはず」で終える。実行していないことは「未確認」と書く
- Best-of-N を発動条件と関係なく自分の判断で起動すること
